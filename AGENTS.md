- Keep canonical section addresses stable: dashboard home at dash.jenvu.com/overview with child pages at dash.jenvu.com/<page> (usage, api, billing, payment), sign-in at auth.jenvu.com/sign-in, blog at blogs.jenvu.com, help at support.jenvu.com, and global public pages on jenvu.com to avoid section-slug collisions.
- Centralize sign-out through the cross-domain session helper so local tokens and the shared `.jenvu.com` cookie are cleared before redirecting to `auth.jenvu.com/sign-in`; this prevents session restoration races and blank auth pages.
- Build authenticator 2FA setup from the auth service's returned QR/URI and remove incomplete factors before retrying; this avoids mismatched secrets and duplicate enrollment failures.
- Subdirectories have their own `AGENTS.md` (chart rules incl. series and gold feed in `src/lib/chart/`, Terminal UI in `src/components/terminal/`, homepage in `src/components/home/`, Solutions/Products in `src/components/industry/`); read them before changing files there.
- MCP server lives in `src/lib/mcp/` (one tool per file, OAuth via the backend issuer, caller token forwarded so RLS applies): keeps external assistants scoped to the signed-in user's own data.
- Terminal access is decided server-side in `src/lib/terminal-access.server.ts` (tested): the Terminal is open to every signed-in user; paid Terminal features (locked chart strategies) follow `checkPlanAccess`/`evaluatePlanAccess` (admin, Founding with 2-day ID window, active paid plan or running trial; credit never unlocks): a UI-only lock could be bypassed via server functions.
- Other public pages share `src/components/PageShell.tsx` (Platform look; `--gc-blue*` tokens in `src/styles.css` are black site-wide, change color there); Pricing and Contact apply it inline: restyle once, not per page.
- `html, body` use `overflow-x: clip` (not `hidden`): `hidden` turns body into a scroll container and breaks every sticky header/bar.
- Free trial (Pro days + credit) starts only when the user clicks "Start free" via the `claim_free_trial()` DB function, tracked once per user in `free_trial_claims`; sign-up no longer grants it: keeps the grant one-time and server-enforced.
- Dashboard pages use the top bar in `src/components/dashboard/DashboardTopBar.tsx` plus an xAI console-style sidebar that is pinned on desktop (drawer on phones; on the Terminal a slim icon-only rail on desktop that opens the full drawer); console cards/pills come from the `.console-*` rules at the end of `src/styles.css`: one consistent console look everywhere.
- Ask Jenvu (free, per-IP limit): facts in `ask-jenvu-knowledge.server.ts`; contact-sales reuses `submitContactMessage`: one inbox.
- Text AI calls try OmniRoute first (`OMNIROUTE_FIRST` in `ai-gateway.ts`; `gatewayChainFor` puts `omniroute/` routes first), AWS only if `AWS_FIRST`, then Lovable/CodeCraft: owner wants OmniRoute before paid AWS credit.
- Site search is built in `src/lib/site-search.functions.ts` (help/story matches plus Firecrawl web results) with the page list in `src/lib/site-pages.ts`; the public header search (`src/components/HeaderSearch.tsx`), dashboard top bar and `/search` all use them, and the header falls back to Ask Jenvu when nothing matches: one search source. Dashboard Chat live data (Google Maps leads, Firecrawl website/web) is fetched server-side in `chat-live-data.server.ts`, rules in `chat-live-data.ts` (tested), injected before the AI call: the AI never invents leads.
- Every top-level public page must be in GLOBAL_PATHS in `src/lib/url-rewrite.ts` (tested); shared dashboard/public slugs resolve by host, public on apex and dashboard on dash, to prevent redirect loops and section 404s.
- Top-bar Gifts box lists positive credit-ledger rows whose reason is in `GIFT_REASONS` (`src/lib/gifts.ts`, tested), with the seen time kept per user in the browser: gifts need no extra table and only gift-type credit shows.
- The Terminal stays unzoomed but its top bar and menu drawer use `.jenvu-zoom-chrome` (same breakpoints as `.jenvu-zoom-dashboard`): keeps header/menu the same size on every dashboard page.
- Blog articles reach Google by resubmitting `https://jenvu.com/sitemap.xml` through the Search Console connector (`submitToGoogle` in `generate-insight.ts`), once per run: the per-URL Indexing API returns 404 through the connector.
- Settings is a group of pages listed once in `SETTINGS_PAGES` (`src/components/settings/SettingsNav.tsx`): General `/dashboard/settings`, Personal `/dashboard/profile`, Security, Billing, Payments, Documents; on any of them the dashboard sidebar swaps to a Back + Settings list, and old `/dashboard/profile#section` links redirect to the page holding that section; wrapping a page in `<SettingsFlat>` switches every `SettingsCard`/`SettingsRow` inside it to the borderless list look (used by General and Documents): one list drives the sidebar and the page set, one switch drives the flat look.
- Founding renewals run in the database (`process_founding_renewals()` hourly via pg_cron; `renew_founding_plan()` called from `applyPlanForPayment` when an order is approved); the dashboard notice reads `src/lib/renewal.ts` (tested): 3 unpaid days then Free; no credit until a payment is approved; credit lots are capped at 31 days by a DB trigger.
- Sign-up abuse checks live in `src/lib/custom-auth.server.ts` with pure limits in `src/lib/signup-guard.ts` (tested), including the one-person check against recent `login_events` IPs/devices; every account uses its plan bot target (`targetsFor`); new-login alerts are recorded server-side by `recordLogin` in `src/lib/login-alert.functions.ts` into `login_events`, with the one-alert-per-login rule in `shouldAlertLogin` (`src/lib/login-alert.ts`, tested): the browser can't skip or fake them.
- Cloudflare Turnstile guards email sign-in and sign-up: the server checks the token (`checkTurnstile` in `src/lib/turnstile.ts`, tested) before `signInWithTurnstile`/`requestSignupOtp` run, and the check stays off until `TURNSTILE_SITE_KEY` + `TURNSTILE_SECRET_KEY` are set: a browser-only check could be skipped.
- JX Bot (MT5) licenses: pure rules in `src/lib/mt5-licenses.ts` (tested), server fns in `mt5-licenses.functions.ts`, validator at `/api/public/licenses/validate` (always HTTP 200); only an active paid (non-trial) plan unlocks the bot, download is a signed link from the private `bot-files` bucket: credit must never enable it. Bot has no license key: user registers an IP on the site, types it in the EA (MyIP), server checks it equals the caller IP; binding stored as "ip" or "ip#account" in `mt5_licenses.mt5_account` (logic in `mt5-ip-license.server.ts`), 1 IP = 1 MT5 account, 1 IP across all users: user wanted IP verification instead of keys.
- Public API model IDs map to exactly one configured upstream model; service errors use the allowlist in `jenvu-api-errors.ts` with original HTTP status, never raw diagnostics: preserves model choice and keeps provider configuration private. The dashboard Chat playground (`playground.functions.ts`, rules in `playground.ts`) uses the API's entitlement, billing and trust rules; the chosen model is tried on Lovable AI first (`LOVABLE_MODEL_MAP`), a backup answers only if it fails and the reply names the model that answered (`publicIdForRoute`). Attachments are read in the browser (`chat-attachments.ts`), images checked by `sanitizePlaygroundImages`: no file storage. Code, images, documents, uploads and site reports share one tab row in `ChatCodeStudio.tsx` (```document opens `ChatDocView.tsx`), files merged by `mergeWorkspace` (no file cap, chat-files.ts, tested); images stream from `/api/chat-image` into the left frame; renames and duplicates (`parseDuplicateRequest`) run locally; changes asked with a duplicate go to the copy only; the chat stays per account in browser storage (`chat-session.ts`, tested) until New chat.
- JX Bot reports (`/api/public/licenses/report`, once a minute from the EA) feed Bot Usage and its ON/OFF log; the plan daily target applies to each license separately (user choice), checked from that account's own profit only.
- Billing renders its plan action from the cached credit-state response, not a separate subscription hook, so the balance and plan action resolve together without a false Free-state flash.
- Bot Usage account delete is decided server-side by `botAccountDeleteBlock` in `src/lib/mt5-licenses.ts` (tested): accounts live on an active IP license or reporting in the last 3 minutes can never be removed.
- Site-wide dashboard notices (updates, new bot, issues) come from `site_announcements` (admins post at `/dashboard/admin/announcements`), dismissed per user in `announcement_dismissals`; which one shows is `pickAnnouncement` in `src/lib/announcements.ts` (tested): one notice source, stays until each user dismisses it.
- Both JX Bot IP managers use `countIpLicenses` from `mt5-licenses.ts` for slot counts: legacy account-only rows have no IP and the server reuses them when an IP is added.
- The Models page (`/models` and `/dashboard/models`) renders `src/components/models/ModelsExplorer.tsx` from `src/lib/model-catalog.ts`, which must hold one entry per `PUBLIC_API_MODEL_IDS` id (tested): the page can never list a model the API doesn't serve.
- Site black/white theme is one choice in `src/lib/site-theme.ts` (tested): public pages get `.dark` on `<html>` (boot script in `__root.tsx` prevents a white flash), the footer Sun/Moon button and the dashboard's own switch both save it; `<html>` never gets `.dark` under /dashboard because the dashboard wrapper applies its own `dark dash-dark` class on every page except the Terminal (own switch); dashboard white/black colors live in the scoped `.jenvu-zoom-dashboard` rules at the end of `src/styles.css`.
- Chat replies run as `chat_jobs` rows: `playgroundChat` (with `jobId`) keeps working via `keepAlive` (`src/lib/keep-alive.server.ts`, Workers `waitUntil` captured in `src/server.ts`) and saves the result; the page keeps the pending id in browser storage and polls `getChatJob` on return; Stop calls `stopChatJob` (stopped replies are not charged): replies survive leaving the page.
- Public (non-dashboard) pages are wrapped in `.jenvu-public-scale` in `__root.tsx` (one desktop zoom in `src/styles.css`): resize the whole public site in one place, dashboard untouched.
