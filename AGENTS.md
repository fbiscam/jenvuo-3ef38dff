- Keep canonical section addresses stable: dashboard home at dash.jenvu.com/overview with child pages at dash.jenvu.com/<page> (usage, api, billing, payment), sign-in at auth.jenvu.com/sign-in, blog at blogs.jenvu.com, help at support.jenvu.com, and global public pages on jenvu.com to avoid section-slug collisions.
- Centralize sign-out through the cross-domain session helper so local tokens and the shared `.jenvu.com` cookie are cleared before redirecting to `auth.jenvu.com/sign-in`; this prevents session restoration races and blank auth pages.
- Build authenticator 2FA setup from the auth service's returned QR/URI and remove incomplete factors before retrying; this avoids mismatched secrets and duplicate enrollment failures.
- Subdirectories have their own `AGENTS.md` (chart rules incl. series and gold feed in `src/lib/chart/`, Terminal UI in `src/components/terminal/`); read them before changing files there.
- MCP server lives in `src/lib/mcp/` (one tool per file, OAuth via the backend issuer, caller token forwarded so RLS applies): keeps external assistants scoped to the signed-in user's own data.
- Terminal access is decided server-side in `src/lib/terminal-access.server.ts` (`evaluateTerminalAccess`, tested): only admins and approved Founding members (2-day ID window after approval; submitted docs keep access); paid plans, trial and credit never unlock it (plans cover JX Bot + Top AI Models): a UI-only lock could be bypassed via the chart server function.
- The homepage (`src/routes/index.tsx`) renders the original Cloud sections (`CloudHome`, `CloudFeatureVideos`, `CloudSolutions`); `HomeBusinessSections.tsx` (colours/motion via `--biz-*` tokens and `.biz-*` classes in `src/styles.css`); older section files in `src/components/home/` are kept unused for quick rollback. Dashboard pages get the Platform look from the scoped `.jenvu-zoom-dashboard main` rules at the end of `src/styles.css`: restyle there once instead of per page.
- Solutions and Products pages render `src/components/industry/IndustryPage.tsx` from a content object per route, each with its own layout variant (no extra sections beyond the existing ones), styled with the API Platform page's look (pills, aurora gradient tiles with white icon chips instead of photos, soft borders): keeps the two pages distinct but consistent with Platform.
- Other public pages (Overview/About, Help, Docs, legal, Development…) share `src/components/PageShell.tsx`, which carries the same Platform look (blue pill buttons, aurora tiles/strips, soft bordered cards); Pricing and Contact apply it inline: restyle there once instead of per page.
- `html, body` use `overflow-x: clip` (not `hidden`): `hidden` turns body into a scroll container and breaks every sticky header/bar.
- Free trial (Pro days + credit) starts only when the user clicks "Start free" via the `claim_free_trial()` DB function, tracked once per user in `free_trial_claims`; sign-up no longer grants it: keeps the grant one-time and server-enforced.
- All dashboard pages, including the Terminal, use the top bar in `src/components/dashboard/DashboardTopBar.tsx` and a menu drawer that stays closed until opened from it: one consistent console look everywhere.
- Ask Jenvu: matched knowledge from `ask-jenvu-knowledge.server.ts` via `ask-jenvu.functions.ts`; contact-sales reuses `submitContactMessage`: one fact source, one inbox.
- While `LOVABLE_CHAT_FIRST` is on in `ai-gateway.ts`, every AI call (chat, articles, analysis, reviews) answers through the single cheap Lovable model `BACKUP_CHAT_MODEL` first, then its CodeCraft chain; user chat (`backupFallback`) additionally tries every other CodeCraft model, then the user's fallback API. Why: owner wants low-cost Lovable AI and CodeCraft keys currently have no balance.
- Site search is built in `src/lib/site-search.functions.ts` (help/story matches plus Firecrawl web results) with the page list in `src/lib/site-pages.ts`; the public header search (`src/components/HeaderSearch.tsx`), dashboard top bar and `/search` all use them, and the header falls back to Ask Jenvu when nothing on the site matches: one search source everywhere.
- Every top-level public page must be listed in GLOBAL_PATHS in `src/lib/url-rewrite.ts` (tested in `url-rewrite.test.ts`): otherwise section hosts like support.jenvu.com prefix it into their section and show Not found.
- Top-bar Gifts box lists positive credit-ledger rows whose reason is in `GIFT_REASONS` (`src/lib/gifts.ts`, tested), with the seen time kept per user in the browser: gifts need no extra table and only gift-type credit shows.
- The Terminal stays unzoomed but its top bar and menu drawer use `.jenvu-zoom-chrome` (same breakpoints as `.jenvu-zoom-dashboard`): keeps header/menu the same size on every dashboard page.
- Blog articles reach Google by resubmitting `https://jenvu.com/sitemap.xml` through the Search Console connector (`submitToGoogle` in `generate-insight.ts`), once per run: the per-URL Indexing API returns 404 through the connector.
- Settings (`/dashboard/profile`) is one page of section cards from `src/components/settings/` (Profile, Security, Preferences, Active sessions, Danger zone); `/dashboard/security` only redirects there: one place for every account setting.
- Founding renewals run in the database (`process_founding_renewals()` hourly via pg_cron; `renew_founding_plan()` called from `applyPlanForPayment` when an order is approved); the dashboard notice reads `src/lib/renewal.ts` (tested): payments are manual crypto orders, so the server must own due dates and downgrades.
- Sign-up abuse checks live in `src/lib/custom-auth.server.ts` with pure limits in `src/lib/signup-guard.ts` (tested), including the one-person check against recent `login_events` IPs/devices; per-account bot target overrides live in `targetsFor` in `src/lib/mt5-licenses.ts`; new-login alerts are recorded server-side by `recordLogin` in `src/lib/login-alert.functions.ts` into `login_events`, with the one-alert-per-login rule in `shouldAlertLogin` (`src/lib/login-alert.ts`, tested): the browser can't skip or fake them.
- JX Bot (MT5) licenses: pure rules in `src/lib/mt5-licenses.ts` (tested), server fns in `mt5-licenses.functions.ts`, validator at `/api/public/licenses/validate` (always HTTP 200); an active plan or the 14-day free trial (until `current_period_end`) unlocks the bot, download is a signed link from the private `bot-files` bucket: credit must never enable it. Bot has no license key: user registers an IP on the site, types it in the EA (MyIP), server checks it equals the caller IP; binding stored as "ip" or "ip#account" in `mt5_licenses.mt5_account` (logic in `mt5-ip-license.server.ts`), 1 IP = 1 MT5 account, 1 IP across all users: user wanted IP verification instead of keys.
- Public API model IDs map to exactly one configured upstream model; service errors use the allowlist in `jenvu-api-errors.ts` with original HTTP status, never raw diagnostics: preserves model choice and keeps provider configuration private.
- JX Bot reports (`/api/public/licenses/report`, once a minute from the EA) feed Bot Usage and its ON/OFF log; the plan daily target applies to each license separately (user choice), checked from that account's own profit only.
- Billing renders its plan action from the cached credit-state response, not a separate subscription hook, so the balance and plan action resolve together without a false Free-state flash.
- Bot Usage account delete is decided server-side by `botAccountDeleteBlock` in `src/lib/mt5-licenses.ts` (tested): accounts live on an active IP license or reporting in the last 3 minutes can never be removed.
- Site-wide dashboard notices (updates, new bot, issues) come from `site_announcements` (admins post at `/dashboard/admin/announcements`), dismissed per user in `announcement_dismissals`; which one shows is `pickAnnouncement` in `src/lib/announcements.ts` (tested): one notice source, stays until each user dismisses it.
- Both JX Bot IP managers use `countIpLicenses` from `mt5-licenses.ts` for slot counts: legacy account-only rows have no IP and the server reuses them when an IP is added.
- The Models page (`/models` and `/dashboard/models`) renders `src/components/models/ModelsExplorer.tsx` from `src/lib/model-catalog.ts`, which must hold one entry per `PUBLIC_API_MODEL_IDS` id (tested): the page can never list a model the API doesn't serve.
