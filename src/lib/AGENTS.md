# Shared business rules

- Customer-facing JX Bot daily target and drawdown copy must interpolate DAILY_TARGET_PCT and DAILY_DRAWDOWN_PCT from mt5-licenses.ts, not duplicate rates or display legacy fixed-dollar daily targets: keeps pricing, guides and AI knowledge aligned with server enforcement.
- Founding JX Bot access is decided by DB `founding_bot_check()` (hourly `process_founding_bot_milestones()`), mirrored in `founding-bot.ts` (tested), and the sidebar JX Bot lock uses the same `readPlan` result via `getJxBotNavAccess`: one rule for the EA validator, page and menu.
- A Founding trial plan ends at `trial_ends_at` in `process_founding_renewals()` with no grace and its `founding_trial_grant` credit is zeroed: the Founding month is a fixed term, not a renewal.
- Billing plan bullets come from `planFeatures` in `plan-features.ts` and the JX Bot page button from `jxBotAction` in `founding-bot.ts` (both tested): JX Bot is shown only to verified Founding members, others see Terminal + API credit.
- Plan prices live only in `plan-pricing.ts` (tested): Terminal + API price for everyone, plus the JX Bot cost for `isVerifiedFoundingMember`; pricing page, Payments and `applyPlanForPayment` all read it, and a paid plan runs JX Bot only for verified Founding members (`readPlan`, `checkBotByIp`): the DB `plans.price_usd` is not used for charging.
- Founding API credit is added only by the admin Fund action (`updateFoundingApplication` approved->active, ID must be verified) via DB `release_founding_credit()`; Founding Terminal access needs a verified ID and ends 30 days after approval (`evaluateFoundingRow`, tested); seat limit/reopen date in `founding-seats.ts` (tested): one server path grants credit and access.
- Plan CTAs use `BuyNowButton`/`BuyBlockedDialog` (`src/components/BuyNowButton.tsx`): Apply now signed out, Buy now signed in, blocked notice until ID verified: one CTA rule everywhere.
- Founding form duplicates are decided by `foundingReapplyDecision` (`founding-reapply.ts`, tested) using server-key lookups: under-review blocks, rejected or account-removed applicants reopen, live/finished members are told to sign in.
